Provisions CRM — About / Architecture

Delivery-grade README · single-file build · Irish food-processor domain

Contents 1 · Business model 2 · Event-driven pipeline 3 · Credit & settlement 4 · Irish compliance (Bord Bia · DAFM · SLA) 5 · Table reference

1Business model — one parent, five children

Companies is the single parent entity. Every other record carries a companyId foreign key back to it; deleting a company cascades through all five child tables (contacts, deals, orders, tickets, tasks).

companies PK · id
contactsFK companyId · exactly one primary
dealsFK companyId + contactId (decision-maker)
ordersFK companyId · optional dealId (null = ad-hoc)
ticketsFK companyId · optional orderId + contactId
tasksFK companyId + polymorphic link to one of Deal / Ticket / Order
  • One company → many contacts, exactly one flagged isPrimary — the decision-maker every deal must reference before it can advance.
  • One company → many deals; one deal → many orders. Every Closed Won appends a fresh fulfillment order (repeat wins keep full history, never collapse to one row).
  • Orders link back via dealId (null = ad-hoc top-up outside any deal) and forward to tickets via orderId when fulfillment breaks.
  • Tasks use a polymorphic FK (relatedToType + relatedToId) so one task relates to at most one of Deal / Ticket / Order — resolved in-app by DB.resolveRelated(), always through DB.* joins, never raw arrays.

2Event-driven pipeline — status changes create work

Deal → Closed Wonauto-creates fulfillment order (Pending)
→
Order → Delivereddock-signed · dispatches AR chase task (Net +N days)
→
Task → Donecash received · settles order to Paid
  • Orders advance one step at a time: Pending → In Production → In Transit → Delivered → Paid (+ Delayed side-state, Cancelled terminal). A Delayed order auto-opens an Urgent ticket.
  • Deals are guarded by blockers: amount > €0, linked primary contact, zero active P1 tickets, score ≥ 60 to close, and no credit-hold breach.
  • Tickets gate deals too — an active Urgent ticket freezes every open deal for that company until Resolved / Closed.

3Credit exposure & settlement — money has one choke point

Completing a payment-chase task runs settlePaymentTask() — a single guarded transition that stamps paidAt on both task and order, flips the order to Paid, releases outstandingAr immediately, and unfreezes CreditHold → Active when exposure drops back inside the limit. Settled chase tasks are terminal receipts: locked, never reopened, never deleted.

4Irish compliance — Bord Bia · DAFM · cold-chain SLA

Bord Bia traceability

Missing Quality Mark sets a compliance blocker: dispatch is held, won-deal closure warns, and the audit trail (mock recall drill, lot LOT-IE-2026-BEEF-9941) proves farm-to-fork traceability.

DAFM establishment numbers

Every company carries a validated approval code (IE 542 EC format, country-aware hints). Duplicates are rejected at the form gate — no two plants share one number.

06:00 CDC cut-off SLA

Each account stores its DC cut-off (05:30 Donabate, 06:00 Newbridge…). A live countdown in the header tracks the next breach; missed cut-offs surface as SLA tickets that block deal progression.
